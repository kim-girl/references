# 프로젝트 계획

## 확정한 요구사항

- 제작자 개인의 개인적 용도로 사용한다.
- 연출의 영감을 얻고 레퍼런스 영상을 다시 확인한다.
- 기억해 둔 기능 설명 영상을 다시 찾는 용도로도 사용한다.
- 정적 웹사이트로 관리하고 사이트 내부 검색을 제공한다.
- AI 비서에게 영상 링크를 전달하면 분석과 데이터 수집을 거쳐 콘텐츠를 추가하고 GitHub Pages에 출판한다.
- 외부 검색 엔진에 노출할 필요가 없으며 모든 페이지에 `noindex`를 적용한다.
- 링크를 아는 다른 사람의 열람을 허용하며 로그인이나 접근 제한은 두지 않는다.
- 주요 영상 출처는 Instagram과 YouTube다.
- 영상 수집과 분석은 `yt-dlp`를 사용하는 외부 Hermes 서버가 담당한다. 사이트에는 플랫폼별 수집 기능을 구현하지 않는다.
- 이 프로젝트는 수집 결과를 표시하는 정적 사이트를 담당한다. 외부 에이전트가 콘텐츠를 추가할 수 있도록 데이터 형식을 정한다.
- 상세 페이지는 스크린샷·설명·대본과 원본 링크를 제공한다.
- 원본 링크는 항상 제공하며, YouTube처럼 임베드를 지원하는 플랫폼은 임베드도 기본 표시한다.
- 사이트에서 수집한 영상 파일을 직접 제공하지 않는다.
- 기본 분류인 카테고리와 보조 분류인 태그를 함께 제공한다.
- 카테고리는 참고 목적 기준으로 나누며, 초기 목록은 `연출`, `촬영`, `편집`, `모션 그래픽`, `도구·기능 사용법`이다.
- 한 영상에 복수 카테고리를 허용한다.
- 카테고리는 나중에 손쉽게 변경할 수 있어야 한다.
- 카테고리 목록은 한 파일에서 관리하고 고정 ID와 표시 이름을 분리한다. 이름 변경 시 영상 데이터의 카테고리 참조를 수정할 필요가 없도록 한다.
- 카테고리 변경은 Hermes에게 요청해 파일을 수정하고 재출판한다. 병합·삭제·재분류 시 관련 영상 데이터도 함께 수정한다.
- 사이트 내 카테고리 관리 화면은 만들지 않는다.
- 태그는 보수적으로 관리하고 기존 태그를 우선 재사용한다.
- 검색 대상은 제목·설명·카테고리·태그·대본·주요 장면 설명이다.
- 검색 결과에 일치한 문구를 표시하고, 제목·태그가 일치하는 결과를 우선한다.

## 계획을 구체화할 순서

1. 사용자와 활용 상황 결정 → 실제 영상 찾기 시나리오로 확인한다.
2. 분류·검색·상세 화면과 수집 데이터 결정 → 예시 영상 하나로 필요한 정보를 점검한다.
3. AI 수집·검토·출판 흐름 결정 → 분석 실패와 수정 상황을 점검한다.
4. 구현 단계 정리 → 단계별 완료 기준을 명시한다.

## 검증 기준

- 생성된 모든 HTML 페이지에 `noindex`가 있는지 확인한다.
- 카테고리의 표시 이름을 변경했을 때 영상의 분류가 유지되고 변경된 이름이 표시되는지 확인한다.
- 제목에 없는 기능 이름이 대본 또는 주요 장면 설명에만 있어도 해당 영상을 검색할 수 있는지 확인한다.
- 검색 결과에 일치한 문구가 표시되고 제목·태그 일치 결과가 우선되는지 확인한다.

## 답변 반영 및 1차 구현

- 질문 문서의 권장안에 동의했으며 PC·휴대폰 모두 최적화한다. 밝고 약간 귀여운 화면으로 구성한다.
- 선택 개인 메모를 AI 설명과 구분하고 검색에도 포함한다. 없는 대본·캡처·메모는 숨긴다.
- 같은 종류의 필터는 OR, 다른 종류와 검색어는 AND로 적용한다. 키워드 검색으로 시작한다.
- Node.js 정적 생성기를 사용해 목록과 영상별 HTML을 만든다. 외부 의존성 없이 상대 경로로 GitHub Pages 하위 경로에 대응한다.
- 카테고리·태그 목록과 영상별 JSON을 분리한다. 추가·수정은 Hermes가 파일로 관리한다.
- 현재 HANDOFF 세 영상의 요약으로 로컬 초안을 구현한다. 실제 캡처와 대본은 아직 없다.
- 현재 YouTube 임베드만 구현한다. 다른 플랫폼의 임베드는 제공 방식 확인 후 추가한다.
- 1차: 데이터·목록·상세·검색 구현 → 필수 데이터 검증과 검색 테스트, PC·모바일 수동 확인.
- 후속: Hermes가 실제 캡처·검수 대본 추가 → 주요 장면과 대본 표시·검색 확인.
- 후속: GitHub Pages 자동 출판 연결 → 검증 실패 시 기존 배포 유지, 성공 시 전체 산출물 배포 확인.
- 수백·수천 건 성능은 후속 실제 자료 확장 시 확인한다. 이번 세 건 검증을 규모 검증으로 간주하지 않는다.

## 1차 검증 결과

- `npm run build`: 세 레퍼런스와 네 HTML 페이지 생성 성공.
- `npm test`: 대본·장면·메모 검색, 제목 우선 순위, 필터 조합, 빈 검색 결과, 모든 HTML의 noindex, 원본 링크와 YouTube 임베드 검사를 포함한 테스트 3개 통과.
- 브라우저: GPT 검색, 연출 카테고리 필터, 교차 필터의 빈 결과, 초기화, 상세 페이지 확인.
- PC·모바일 화면을 확인했고 모바일 390px 목록·상세에서 가로 넘침이 없었다.
- 실제 영상 재생, 실제 캡처·대본 콘텐츠, 대규모 검색 성능, GitHub Pages 배포는 이번 검증 범위 밖이다.

## 캡처 보완

- 사용자의 후속 요청으로 원본 세 영상을 내려받고 각 네 장씩 실제 프레임을 WebP로 추출했다. 시간은 입력 이후 `-ss`로 선택하고 추출 화면을 직접 확인했다.
- 목록 썸네일과 상세 페이지의 시간·장면 설명에 총 12장을 연결했다. 세로 영상은 목록에서 잘리지 않게 표시한다.
- 목록 썸네일 세 장과 상세 장면 네 장의 브라우저 로딩 및 모바일 가로 넘침 없음 확인. 빌드와 캡처 검사를 포함한 테스트를 통과했다.
- 이전의 캡처 미제공 상태는 해소되었다. 대본 전문은 아직 없다. 다운로드한 영상 원본은 사이트 산출물에 포함하지 않는다.
