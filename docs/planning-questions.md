# 계획 확정을 위한 질문

이미 합의한 사항은 [계획 문서](./plan.md)에 기록되어 있습니다. 아래 번호별로 답해 주세요. 권장안에 동의하면 `1. 권장안`처럼 적고, 다른 부분만 설명해도 됩니다. 기술 선택과 수집 구현은 별도로 질문하지 않습니다. 수집은 외부 Hermes의 책임이며, 사이트 구현 방식은 아래 답변을 바탕으로 제안합니다.

## 1. 일부 정보가 없는 영상도 등록할까요?

**권장안:** 제목·원본 링크·설명·카테고리는 필수로 하고, 대본·스크린샷·태그·임베드 정보·제작자·영상 길이는 선택으로 둡니다. 없는 항목은 화면에서 숨깁니다. 모르는 정보를 추측해 채우지 않습니다.

음악만 있는 영상에는 대본이 없을 수 있고, 스크린샷 수집이 실패할 수도 있습니다. 선택 항목을 필수로 두면 자료의 완성도는 일정해지지만 등록이 막힐 수 있습니다.

**답변:** 좋아.

## 2. 상세 페이지의 설명에는 무엇이 필요할까요?

**권장안:** 영상의 짧은 요약과, 제작에 참고할 만한 연출·기법·기능에 관한 설명을 제공합니다. 주요 장면은 시간 위치·스크린샷·장면 설명을 한 묶음으로 표시하고, 대본은 별도 영역에서 펼쳐 볼 수 있게 합니다. 확보한 정보만 표시합니다.

예를 들어 자막 튜토리얼이라면 “무엇을 설명하는 영상인가”와 “어떤 효과를 어떻게 활용할 수 있는가”를 구분해 보여줍니다. 참고 설명 없이 요약만 두는 편이 단순하지만 영감을 얻는 데 필요한 맥락이 줄어듭니다.

**답변:** 좋아.

## 3. 본인이 남기는 메모가 필요할까요?

**권장안:** 선택 항목으로 개인 메모를 두고, AI의 설명과 구분합니다. 메모도 검색 대상으로 포함합니다. 링크를 전달할 때 “이 도입부 분위기가 좋음”처럼 적은 내용이나, 나중에 Hermes에게 요청한 메모를 보관합니다. 사이트 내 편집 화면은 만들지 않습니다.

저장 이유가 남으면 나중에 다시 찾기 쉽습니다. 다만 메모 역시 링크를 아는 다른 사람이 볼 수 있습니다. 필요하지 않으면 첫 버전에서 제외할 수 있습니다.

**답변:** 좋아.

## 4. 첫 화면은 어떻게 둘러보면 좋을까요?

**권장안:** 검색창·카테고리 필터·태그 필터와 썸네일 카드 목록을 제공합니다. 기본 정렬은 최근 추가순이며, 카드에는 제목·짧은 요약·카테고리·태그를 표시합니다. 이미지가 없으면 텍스트 카드로 표시합니다. 별도 즐겨찾기나 평가 기능은 첫 버전에서 제외합니다.

카드 목록은 영감을 얻으며 둘러보기 좋습니다. 텍스트 중심 목록은 한 화면에 더 많은 자료를 표시할 수 있습니다.

**답변:** 좋아.

## 5. 복수 필터를 선택했을 때 어떤 결과를 원하나요?

**권장안:** 같은 종류 안에서는 하나라도 일치하면 표시하고, 종류 간에는 모두 만족해야 합니다. 예를 들어 카테고리 `편집`, `모션 그래픽`과 태그 `자막`을 선택하면 두 카테고리 중 하나에 속하면서 `자막` 태그가 있는 영상을 표시합니다. 검색어가 있으면 그 조건도 함께 적용합니다.

이 방식은 카테고리로 넓게 고르고 태그로 좁히기 좋습니다. 선택한 모든 카테고리에 동시에 속하도록 하면 결과가 더 적어집니다.

**답변:** 좋아.

## 6. 검색어는 어느 수준으로 이해하면 충분할까요?

**권장안:** 첫 버전은 한국어·영어 키워드 검색으로 시작합니다. `자막`, `인터뷰 도입부`, `After Effects` 같은 단어나 짧은 구절로 찾고, 질문형 문장의 의미를 해석하는 AI 검색은 제외합니다. 한국어 검색 품질은 실제 예시 자료로 검증합니다.

“차분한 분위기의 인터뷰 시작 장면 찾아줘” 같은 문장까지 의미로 찾으려면 별도의 검색 설계가 필요합니다. 해당 수준이 꼭 필요하면 알려주세요.

**답변:** 좋아.

## 7. PC와 휴대폰 중 어느 쪽을 우선할까요?

**권장안:** 둘 다 사용할 수 있게 하되 PC에서 탐색과 상세 정보 확인을 우선합니다. 휴대폰에서도 검색·필터·원본 링크 이동을 편하게 제공합니다.

주로 Instagram을 휴대폰으로 보며 참고 자료를 확인한다면 휴대폰 중심 화면이 더 적합할 수 있습니다.

**답변:** 둘다 편하게 최적화.

## 8. 첫 화면에서 예상하는 자료 규모는 어느 정도인가요?

**권장안:** 처음에는 수백 개, 이후 수천 개까지를 기준으로 계획합니다. 검색과 이미지 로딩이 이 범위에서 원활한지 확인합니다.

정확한 숫자는 필요하지 않습니다. 예상보다 큰 규모를 미리 대비하면 초기 구성이 불필요하게 복잡해질 수 있어 대략적인 범위만 정합니다.

**답변:** 좋아.

## 9. 같은 원본 영상의 링크를 다시 전달하면 어떻게 할까요?

**권장안:** 새 레퍼런스로 중복 등록하지 않고 기존 항목을 갱신합니다. 개인 메모는 유지합니다. 플랫폼과 영상 식별자를 확보할 수 있으면 그것으로, 그렇지 않으면 정리된 원본 URL로 동일 영상을 구분합니다. 판별과 갱신은 Hermes가 담당하고 사이트 데이터 규칙에 이를 명시합니다.

같은 영상을 목적별로 별도 등록하면 다른 메모를 남기기 쉽지만 검색 결과에 중복이 생깁니다. 이미 복수 카테고리와 태그를 허용하므로 하나의 항목을 유지하는 쪽을 권장합니다.

**답변:** 좋아. 이를 위해 URL은 정규화하라고 AGENTS.md나 스킬에 적어야겠다. 참고로 내가 테스트하면서 만든 스킬과 테스트 handoff 문서를 docs에 넣었으니 확인해 봐.

## 10. 콘텐츠 추가 후 출판은 자동으로 진행할까요?

**권장안:** Hermes가 데이터와 이미지를 저장하고, 데이터 검증·사이트 빌드가 성공하면 별도 사람 승인 없이 출판합니다. 검증에 실패하면 기존 사이트를 유지합니다. 수집 과정 자체는 이 프로젝트에서 구현하지 않고, Hermes가 따라야 할 입력 형식과 검증·출판 절차를 문서화합니다.

출판 전에 직접 확인하는 방식을 선택하면 잘못된 AI 설명을 발견할 기회가 있지만 매번 확인해야 합니다. 자동 출판을 선택하더라도 내용의 사실성까지 빌드 검증으로 보장할 수는 없습니다.

**답변:** ㅇㅇ

## 11. 화면 디자인에서 원하는 분위기나 참고 사이트가 있나요?

**권장안:** 밝은 배경에 이미지 중심 카드와 읽기 쉬운 상세 페이지로 시작합니다. 꾸밈보다 스크린샷과 설명을 확인하기 쉽게 구성합니다. 첫 버전에서 테마 전환은 제외합니다.

어두운 배경이나 특정 참고 사이트를 선호하면 적어 주세요. 선호가 없다면 권장안으로 진행합니다.

**답변:** ㅇㅇ. 그리고 좀 귀여우면 좋을 듯.

## 답변 이후 만들 최종 계획

- 화면 구성과 실제 탐색 시나리오
- 영상·장면·카테고리·태그의 데이터 형식과 필수·선택 항목
- Hermes가 따를 콘텐츠 추가·수정 규칙
- 정적 사이트 생성·내부 검색·GitHub Pages 배포 방식
- 작은 구현 단계별 산출물과 검증 기준

추가 질문은 답변 사이에 모순이 있거나 구현 범위를 결정할 수 없는 부분이 있을 때만 묶어서 정리합니다.
